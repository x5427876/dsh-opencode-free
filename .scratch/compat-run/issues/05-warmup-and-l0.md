# 05: 暖機與 L0

Spec: `../spec.md`

## What to build

外掛啟動時會自動做一輪探測（probe），上一輪實測就是它把匿名額度用掉的原因之一。讓相容性驗證先做一次暖機，讓這輪探測只發生一次，並把它的結果當作 L0（模型在 DSH picker 中且在 Zen 列表裡）的資料，使這筆額度不是浪費。

- 先跑暖機進程，等外掛的自動探測完成。
- 暖機結果成為每個模型的 L0 判定。
- 之後各模型的進程不再觸發探測。
- 不讀外掛內部快取檔的格式；取得方式依 #01 的結論。

若 #01 推翻或未驗證「暖機結果能經公開行為取得」，本票先依 #01 提出的替代方案調整，或回到 spec 重新決定，再動工。

## Acceptance criteria

- [ ] 暖機只執行一次，且早於任何模型的驗證
- [ ] 暖機結果出現在報告的 L0 欄位
- [ ] 模型進程不再重複觸發探測（以注入的驅動器呼叫記錄觀察）
- [ ] 實作不依賴外掛內部快取檔的格式
- [ ] 暖機失敗時有明確行為與報告說明，不會讓整輪靜默通過
