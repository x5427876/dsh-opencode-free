# 共用匿名工具選擇策略與官方動態全模型相容性驗證

## Problem Statement

免費模型可以經真實 DSH 完成文字、讀檔與 PowerShell 往返，但插件內建探測仍可能失敗。已重現的原因是：無宿主工具時，插件加入補位工具，同時強制設定 `tool_choice: "none"`。指定模型的 Responses 通道拒絕這個值並回傳 HTTP 400。只移除此欄位可得到 HTTP 200 與成功探測；恢復原設定又回到 HTTP 400。

這個問題會影響探測與其他無工具匿名請求。只修單一模型會留下其他入口與新模型的相同風險。直接允許補位工具執行，則會宣稱宿主具有不存在的能力。

目前相容性驗證也不能可靠表達「所有模型通過」。L0 失敗、上游拒絕、上游不可用或空目標清單，仍可能得到退出碼 0。讀檔與 shell 步驟只查回覆是否包含 nonce 或雜湊，沒有確認 DSH 實際執行指定工具。若驗收目標沿用插件目前可見清單，插件漏列的官方新模型也可能一起消失。

使用者要求先核對 DSH `0.2.1-alpha.3` 的宿主契約，再調整機制。已完成該版本查核與設計確認。本規格中的相容性驗證指 compat run，不是對話壓縮測試。

## Solution

使用共用匿名准入策略。無宿主工具且呼叫端沒有明確指定工具選擇時，保留實質補位工具宣告，省略插件強制加入的 `tool_choice`。保持宿主工具與補位工具的執行邊界。模型要求呼叫補位工具時，先攔截，再明確回報失敗，不自動重送。

沿用既有相容性驗證流程。每輪從官方動態來源建立所有免費對話模型的驗收目標。以官方目前在列資料、費率與端點資料判定範圍，讓 models.dev 補充能力與推理等級。目標獨立於插件目前的模型目錄，才能發現漏列模型。

完整驗收使用目前工作樹的插件 tarball，在隔離的 DSH `0.2.1-alpha.3` 中執行。每個目標都必須通過 L0 探測、L1 非空文字、L2 read 與 Windows pwsh 往返。利用宿主正式支援的 JSON 事件核對工具執行。只有非空目標集合全數通過，才回傳退出碼 0。

## User Stories

1. As an 匿名使用者, I want 無工具請求不被插件強制加入不相容的工具選擇值, so that 模型不會因插件額外設定而拒絕請求。
2. As an 匿名使用者, I want 探測與一般請求共用相同策略, so that 探測結果能反映實際可用性。
3. As an 使用者, I want 標題與對話壓縮等既有無工具入口套用共用策略, so that 相同問題不會在旁路呼叫復發。
4. As an 維護者, I want 新加入的免費對話模型使用共用規則, so that 不需要維護逐模型例外清單。
5. As an DSH 使用者, I want 補位工具只作准入宣告, so that 插件不會新增未經宿主提供的執行能力。
6. As an DSH 使用者, I want 插件在串流事件與最終結果中攔截補位呼叫, so that 宿主不會執行不存在的工具。
7. As an DSH 使用者, I want 分片工具名稱也受到攔截, so that 不完整事件不會繞過執行邊界。
8. As an 匿名使用者, I want 補位呼叫失敗後明確結束, so that 插件不會自動重送並額外消耗匿名額度。
9. As an 工具使用者, I want 真實宿主工具的選擇語意被保留, so that 正常工具工作不受無工具修復影響。
10. As an provider 呼叫端, I want 明確指定的工具選擇被保留, so that 插件不會靜默改變呼叫意圖。
11. As an Windows 使用者, I want pwsh 名稱與參數在往返後符合宿主契約, so that 工具改名不會改變實際執行語意。
12. As an 讀檔工具使用者, I want read 的路徑與參數往返保持正確, so that 模型讀取的是指定檔案。
13. As an 帶 key 的使用者, I want 匿名准入修復不改寫帶 key 請求, so that 原有認證與工具行為被保留。
14. As an 其他 provider 的使用者, I want 本次調整只作用於既有 Zen 範圍, so that 無關請求保持原行為。
15. As an 維護者, I want 每輪從官方動態清單取得模型, so that 驗收不依賴寫死名單或上輪結果。
16. As an 維護者, I want 以官方費率與端點資料辨識免費對話模型, so that 不會只憑模型名稱判定免費或用途。
17. As an 維護者, I want models.dev 只補充資料而不靜默縮減官方目標, so that 官方新模型不會因補充資料落後而漏測。
18. As an 維護者, I want 官方資料缺漏或互相衝突時列為未確認, so that 不明範圍不會被誤報為完整通過。
19. As an 維護者, I want 非對話模型有明確排除原因與來源, so that 驗收範圍可以核對。
20. As an 維護者, I want 免費對話模型即使缺少插件通道支援也保留在目標中, so that 插件能力不足不會被排除規則隱藏。
21. As an 維護者, I want 驗收目標獨立於插件目前可見清單, so that 模型目錄漏列會成為可觀察的缺口。
22. As an 維護者, I want 報告保存本輪來源時間與目標快照, so that 可以重建本輪實際驗過的範圍。
23. As an 維護者, I want 執行中失敗或下線的模型仍保留原列, so that 不會靠刪除失敗目標達成全部通過。

30. As an 維護者, I want read nonce 與 shell 雜湊使用不同的隨機檔案, so that 一個步驟的答案不能取代另一個步驟。
31. As an 維護者, I want nonce 與預期雜湊都不出現在提示中, so that 模型不能靠回顯提示通過驗收。
32. As an 維護者, I want 缺失、損壞、截斷或無法配對的相關事件不算通過, so that 不完整證據不會產生成功結果。
33. As an 維護者, I want 每個模型保留各層獨立結果, so that 後來成功的文字或工具步驟不會掩蓋先前的 L0 失敗。
34. As an 維護者, I want 只有所有目標完成所有要求才退出 0, so that 命令退出碼能直接支援完整驗收。
35. As an 維護者, I want 本地故障與上游未完成保留不同分類, so that 非零結果不會一律被誤解為插件故障。
36. As an 匿名使用者, I want 保留有限 429 退避與連續限額停止規則, so that 驗收不會無限制消耗共用匿名額度。
37. As an 維護者, I want 帶 key 的對照結果無法取代匿名結果, so that 匿名失敗不會被其他認證路徑掩蓋。
38. As an 維護者, I want 單模型或未啟用工具的窄範圍執行如實標示, so that 窄範圍成功不會被宣稱為全模型完整通過。
39. As an 使用者, I want 測試使用暫存 DSH_HOME 與工作目錄, so that 現有 profile、憑證與執行中的 DSH 不受影響。
40. As an 維護者, I want 預設離線測試不用網路也不讀使用者資料, so that 日常測試可重複且不消耗匿名額度。
41. As an 維護者, I want 原始工具事件只在記憶體比對, so that 報告不洩漏工具輸入、結果、文字或推理內容。
42. As an 維護者, I want 報告列出環境、版本、來源與每層判定, so that 其他人能核對成功與未完成的界限。

44. As an 後續實作者, I want 既有單模型證據與新規格分開保存, so that 歷史診斷不會被當成新標準已完成的證據。

## Implementation Decisions

### 匿名工具選擇與執行邊界

- **共用策略。** 沿用現有 provider 包裝、direct compat 包裝、探測 hook 與最終 payload 補位流程。先辨識呼叫端實際提供的宿主工具，再加入缺少的准入宣告。使用同一個策略決定工具選擇與補位呼叫攔截，避免各入口自行猜測模型能力。
- **無工具預設。** 呼叫端沒有宿主工具，且未明確指定工具選擇時，保留實質 read／bash 補位宣告，省略插件強制加入的 `tool_choice`。同時處理正常 gate 與最終 payload backstop 的兩個現有寫入點。
- **呼叫端語意。** 有真實宿主工具時，保留原本的工具選擇與執行語意。保留呼叫端的明確工具選擇與 payload hook 結果。若呼叫端明確設定的值被上游拒絕，就如實回報；不靜默改成另一種選擇，也不宣稱任意選項都受所有模型支援。
- **補位執行限制。** 補位宣告不增加宿主能力。串流事件與最終結果都必須在補位呼叫成為宿主可執行呼叫前攔截。分片或尚未完整的工具名稱不能繞過檢查。保持真實工具事件的正常順序與參數內容。
- **錯誤與重送。** 補位呼叫須產生可辨識且不包含敏感內容的失敗。不要執行補位工具、重寫對話假裝成功，或自動重送此類失敗。既有 429 退避與此規則分開處理。
- **保留既有契約。** 保留 read、pwsh／bash 的既有名稱與參數往返，以及 session 身份與親和欄位。帶 key 請求、其他 provider 與非目標網路請求保持原行為。輸入 context 與呼叫端選項保持不變。

### 官方動態目標與資料來源

- **目標來源。** 每輪重新讀取官方模型目錄。使用目前官方費率與端點資料辨識免費對話模型。不能用 ID 的 `-free` 後綴、內建表、上輪報告或插件目前可見清單代替官方範圍。
- **補充資料。** models.dev 可補充模型紀錄、能力與推理等級。它不能覆蓋官方成員與分類，也不能因缺少紀錄就讓官方目標消失。官方目錄目前沒有免費或通道欄位；實作須核對官方發布的費率與端點資料，不假設目錄 API 提供這些欄位。
- **分類不明。** 來源抓取失敗、結構改變、分類衝突或資料缺漏時，保留原因並標記未完成。免費資格未確認前不發送該模型的推理請求。只要仍有影響完整範圍的未確認項，就不能宣稱全部通過。
- **範圍區分。** 官方已確認的付費模型與非對話模型另列排除理由及來源。非對話模型不算通過。免費對話模型若缺少插件支援的傳輸或模型紀錄，仍保留為未通過目標，不因能力缺口而排除。
- **本輪快照。** 保存來源 URL、取得時間、目標 ID、排除項與未確認項。當輪目標固定供結果核對。後續下線或失敗的目標仍保留原列；新模型留待下一輪。核對實際探測範圍，明列清單變動，不把不同範圍的結果拼成完整成功。
- **正式目錄邊界。** 正式插件的模型目錄仍由既有目錄決策管理。本次建立獨立驗收目標，以發現正式目錄的漏列；不因此全面改寫使用者可見的目錄政策。

### 宿主流程與驗收判定

- **精確版本。** 保留插件目前版本 0.3.4 與 DSH 0.2.1-alpha.3 的精確相容釘選。安裝前核對 peers，載入插件前核對實際 CLI 版本，報告記錄實際解析的 adapter／pi-ai 版本。不要將本地 0.3.4 產物視為 registry 已發布內容。
- **隔離。** 沿用現有暫存環境、內建 headless profile 與 overlay。安裝目前工作樹打包產物，停用額外標題推理，選取目標 provider／模型。使用匿名 public；只移除測試子進程的 key 與 debug 設定，不改使用者環境或憑證。
- **L0。** 指定目標須在用於模型選取的 provider 目錄中，且本輪實際探測為 ok。保留既有非空文字或 thinking 的探測成功語意。L0 直接呼叫 provider；它不是已經過 DSH adapter 或已驗證 Web 選單的證據。
- **L1。** 經真實 PiAiAdapter 完成指定模型對話，退出碼為 0，且 assistant 最終文字非空。JSON 模式須取有效 final 事件的文字；session、status、thinking 或非空 JSON stdout 本身不算通過。
- **L2 read。** 觀察宿主 read 呼叫，確認路徑指向本輪隨機 nonce 檔案。以呼叫 ID 配對成功工具結果，並在工具結果與最終回覆都驗到該 nonce。nonce 不放進提示。
- **L2 pwsh。** Windows 須觀察還原後的宿主 pwsh 呼叫。確認符合宿主必要參數、預定工作目錄與本輪雜湊命令。使用另一個隨機檔案，於配對工具結果與最終回覆均驗到預期雜湊。預期雜湊不放進提示。其他平台保留原本 shell 分支，不增加跨平台成功宣稱。
- **事件契約。** 使用精確宿主版本正式支援的 JSON 事件。核對工具名稱、必要參數、呼叫 ID、事件順序、結果狀態及唯一有效 final。缺少、損壞、相關欄位截斷或無法配對的證據不算通過。正常額外狀態事件可存在。
- **結果內容。** 工具結果的 completed 狀態只表示宿主未將其標為工具錯誤，不單獨證明 shell 命令成功。仍須驗證 nonce／雜湊。另一個工具取得相同內容，不能取代指定 read／pwsh 的要求。
- **路徑與格式。** 以測試工作目錄解析路徑，接受等價的絕對路徑與平台分隔符號。比對實際命令與測試目標，不強加無關的輸出排版要求。工具輸出、最終回覆與本輪隨機值都須有獨立的比對證據。
- **推理等級。** L1／L2 使用最低已公布且宿主接受的等級；沒有公布等級時保留 default 並如實標記。沿用探測的既有預算與等級策略。這次不宣稱逐一驗過所有推理等級。
- **聚合。** 每個模型保留各層獨立結果。後續成功不覆蓋先前失敗。完整驗收要求同一輪的非空目標集合全部通過 L0、L1、read 與 shell。
- **退出碼。** 直接收緊既有命令，不新增 strict 模式。0 表示非空目標集合完成本輪要求的全部檢查；1 表示 setup／runner 或已確認的插件、宿主整合與必要行為故障；2 表示上游拒絕、不可用、限額、空清單或證據未完成；3 表示參數或版本等前置條件遭拒絕。已確認本地故障優先於上游未完成。保留原因分類，避免把所有非零結果都標為 plugin-fault。
- **有限退避。** 保留模型間隔、429 的 30／60 秒退避及連續三個模型仍限額時停止的規則。其餘目標列為未驗證。不增加無限制輪次，也不把不同輪次的零散成功合併為同一輪通過。
- **窄範圍模式。** 保留既有單模型與未啟用工具的模式。退出碼 0 僅對應該次明示範圍。完整驗收須啟用工具且涵蓋完整官方目標集合；窄範圍成功不能替代它。

### 報告與維護

- **資料保護。** JSON 事件只在記憶體中解析。持久化報告僅保存允許的模型／工具名稱、HTTP 狀態、分類、時間與比對布林。不保存原始 input、result、final.text、推理、憑證或 request body。新錯誤摘要亦遵守此限制。
- **可核對結果。** 報告保存來源與版本、環境、目標及排除快照、要求層級、匿名／帶 key 區別、各層判定、退出碼與整體完成狀態。使用獨立輸出位置，保留既有報告。帶 key 對照不能取代匿名失敗。
- **文件同步。** 更新相關雙語使用說明、相容性驗證文件與未發布變更紀錄，說明新退出碼及完整驗收條件。既有 ADR 保留來源、身份與 live／CI 的責任邊界。不擴大修復無關工程 gap。

## Testing Decisions

沿用設計訪談已確認的接縫。此次 to-spec 不新增訪談，也不要求額外測試專用公開介面。測試驗證使用者可觀察的行為，不只比對私有函式或原始碼字串。

### 1. 公開 provider 與離線 HTTP／串流 fixture

沿用既有 provider、direct compat、payload hook 與 SSE fixture。這是工具選擇策略與補位執行邊界的主要接縫。

- 重現拒絕 tool_choice none 的 Responses fixture。預設無工具請求須省略插件加入的欄位，同時保留有效的准入宣告。
- 覆蓋兩個通道、main／compat、兩種 stream 方法、legacy／normalized context、正常 gate 與最終 payload backstop。
- 覆蓋呼叫端明確工具選擇、真實宿主工具與帶 key 請求，驗證其語意保持不變。
- 模擬完整與分片的補位工具呼叫。確認可執行的補位呼叫不會到達宿主，而不只是最後的 result 拒絕。
- 保留 read／pwsh 的名稱、參數與歷史往返，以及輸入不可變、身份親和與非目標請求不變的必要回歸。

### 2. 既有 compat 流程的注入式離線接縫

沿用目前注入 catalogue、driver、sleep 與報告寫入的方式。將官方目錄、官方費率與端點文件、補充 metadata 及宿主 JSON 輸出替換為固定 fixture；執行真實的分類、比對與聚合邏輯。

- 覆蓋官方新增模型、缺少 models.dev、無免費後綴的免費模型、非對話模型、付費模型、未知通道、來源衝突、文件結構改變與空清單。
- 驗證缺少插件模型紀錄或通道支援不會靜默縮減免費對話目標。驗證排除項有原因且不計為通過。
- 覆蓋 L0 失敗但 L1／L2 成功、403、429、上游不可用、未驗證與空目標造成的假通過。檢查原因分類、各層結果、整體狀態及退出碼一致。
- 使用此宿主版本的 JSON 事件形狀。測試 read 與 pwsh 的成功配對，以及錯誤工具、錯誤路徑／命令、參數缺失、結果錯誤、nonce／hash 不符、final 缺失或重複、事件截斷及不完整配對。
- 驗證一般狀態事件不會被當成答案。只有有意義的 final 與成功完成狀態能滿足 L1。
- 用同一個測試 nonce／hash 檢查內部比對，再檢查報告不含原始工具輸入、結果、對話或憑證。測試來源與呼叫端物件不被原地修改。
- 沿用有限退避、連續限額停止與清理 fixture。確認沒有無限制重送，也沒有暗中詢問窄範圍以外的模型。

### 3. 隔離真實 DSH 的全模型驗收

沿用既有打包、隔離安裝、內建 headless、overlay 與 PiAiAdapter 路徑。這是唯一能證明本輪實際上游與宿主往返通過的接縫。

- 先完成相關離線回歸、完整型別／測試／建置／打包與適用的 tarball consumer 檢查。離線測試不使用網路、不讀使用者 profile，也不消耗匿名額度。
- 完整 live 命令經 pnpm 啟動，指定 DSH 0.2.1-alpha.3、啟用工具、使用獨立輸出目錄，並省略單模型限制。
- 每輪開始取得官方動態資料，保存完整範圍；每個目標必須實際通過 L0／L1／L2。確認臨時環境清除，且既有 DSH／profile／憑證沒有改變。
- live 相容性驗證只在使用者明確授權的範圍內執行。本次產生規格不等於已發出推理請求或已取得無限制重跑授權。
- 403、429、逾時、上游不可用及資料未確認都不能當作通過。若未完成，保留安全報告與未驗證項；完整驗收目標仍未達成。

## Out of Scope

- 升級 DSH、改變精確 peer 釘選、增加插件版本、打 tag、發布套件或 release。
- 新增 System One、Anthropic 或其他目前未支援的傳輸。相關免費對話模型仍須保留為未通過目標，不得以本項排除它們。
- 測試付費模型、猜測免費資格、改用帶 key 或付費路徑來掩蓋匿名失敗。
- 全面改寫正式插件的模型目錄、隱藏偏好、快取與 dead 判定政策。
- 逐模型特例表、無限制重試、長期監控或自動排程。
- 對話壓縮的專門 live 驗收、Web／Desktop UI、既有使用者 profile 或新的跨平台成功宣稱。
- 宣稱所有未來模型、所有推理等級或任意呼叫端工具選項都必然被上游接受。
- 重寫對話、執行補位工具、擴大宿主權限或以工具回覆假裝完成測試。
- 啟動、停止或重啟既有 DSH；刪除使用者 profile；讀取或改寫憑證儲存。
- 將消耗匿名額度的驗收放進 CI，或將本規格視為持續 live 重跑授權。
- 無關工程 gap、傳輸替換、TLS 仿冒、代理服務、新登入機制或全庫重構。
- 本次 to-spec 的程式碼實作、拆票、提交、推送或 live 執行。
