# 04: 讓每層結果、完整範圍與退出碼一致

**Parent:** [功能規格](../spec.md)。此檔為拆票草稿，尚未發布正式票。

**What to build:** 使用者只有在本輪要求的每個目標、每個步驟都成功時，才取得退出碼 0。官方來源缺口、L0 失敗、上游拒絕或未驗證模型都會如實反映在每層結果、整體狀態與命令退出碼。

**Blocked by:** 02「以官方動態來源建立並呈現本輪驗收目標」；03「以宿主 JSON 事件驗證文字、read 與 pwsh 往返」。

**User stories:** 24、26、33–38、40、42–43。

## Acceptance criteria

- [ ] 使用票 02 的來源／目標狀態與票 03 的工具證據，接入既有 runner、Markdown／JSON 報告與 CLI 退出碼。直接收緊既有流程，不另增 strict 模式。
- [ ] L0 須確認模型在 provider 目錄中，且本輪探測為 ok。正常暖機或後續 L1／L2 成功不能覆蓋 L0 失敗；保留非空文字或 thinking 的探測成功語意。
- [ ] 完整驗收要求同一輪的非空官方免費對話目標集合，全部通過 L0、L1、read 與 shell。來源未確認、空集合與資料／能力缺口都不能產生完整成功。
- [ ] 每個模型與每個層級保留獨立結果及原因。模型可見、已測、通過、未完成與排除狀態分開呈現，不改動正式目錄的 dead 語意。
- [ ] 退出 0 僅表示本次明示範圍全部通過；退出 1 表示 setup／runner 或已確認的本地整合與必要行為故障；退出 2 表示上游拒絕、不可用、限額、空清單或證據未完成；退出 3 保留前置條件拒絕。本地已確認故障優先於未完成。
- [ ] 403、429、上游不可用及未驗證模型不再落入成功，但保留原因分類，不一律改成 plugin-fault。帶 key 對照不得覆蓋匿名判定。
- [ ] 保留單模型與未啟用工具的窄範圍模式。報告與成功文案說明實際範圍，不將窄範圍通過宣稱為全模型 L0／L1／L2 通過。
- [ ] 保留既有模型間隔、429 的 30／60 秒退避及連續三模型仍限額時停止的規則。剩餘目標列為未驗證；不無限重跑或跨輪拼接成功。
- [ ] 離線 runner fixture 重現並修正 L0 失敗但後續成功、gate-refused、upstream-down、空目標、來源未確認與缺少工具證據等假通過，並覆蓋窄範圍與全範圍成功。
- [ ] 每個案例核對每層判定、原因、聚合狀態、報告與退出碼一致。安全報告不新增原始工具輸入、對話、結果或憑證。
- [ ] 更新相關雙語命令說明、驗收文件與未發布變更紀錄；保留 ADR-0003 的不進 CI 與 429 不確定判定。本票不發 live 推理請求。
