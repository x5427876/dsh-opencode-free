# 02: 以官方動態來源建立並呈現本輪驗收目標

**Parent:** [功能規格](../spec.md)。此檔為拆票草稿，尚未發布正式票。

**What to build:** 每輪相容性驗證都從官方目前在列、費率與端點資料建立所有免費對話模型的目標。使用者能在命令報告中核對來源、目標、排除項與未確認項。插件漏列或補充 metadata 缺席不會讓目標靜默消失。

**Blocked by:** None (can start immediately).

**User stories:** 15–24、40、42。

## Acceptance criteria

- [ ] 每輪重新讀取官方模型目錄，以目前官方費率及端點資料辨識免費對話模型。models.dev 僅補充能力與推理資料，不以 ID 後綴、內建表、上輪結果或插件可見清單決定目標。
- [ ] 官方資料取得與分類、現有 runner 的目標選取、Markdown／JSON 報告形成完整可驗證路徑；不只交付獨立 parser 或未接線的資料結構。
- [ ] 報告保存來源 URL、取得時間、完整目標 ID、排除原因與未確認項。當輪快照供核對，下一輪重新取得資料。
- [ ] 付費與非對話模型有官方依據才排除，且不算通過。免費對話模型若缺少插件紀錄、補充資料或傳輸支援，仍明列目標及能力缺口。
- [ ] 來源抓取失敗、文件結構改變、資料衝突或免費資格不明時保留安全原因，標記選取未完成。資格未明前不發該模型的推理請求；不退回固定名單。
- [ ] 空目標集合或未解分類不能產生完整通過結果。必要的選取失敗退出 2，前置參數／版本遭拒絕保留退出 3；與其他層聚合的最終判定由票 04 整合。
- [ ] 保留單模型篩選與明確範圍說明；確認目標不存在或不符合免費對話範圍時停止，不自行換模型。
- [ ] 核對實際探測與本輪目標。執行中下線或失敗的目標保留原列；清單變動與額外目標不會被靜默拼成成功範圍。
- [ ] 以官方來源與 metadata 的離線 fixture 覆蓋新模型、缺少 models.dev、無免費後綴、付費、非對話、未知通道、結構改變、來源衝突、空清單及跨輪更新。
- [ ] 同步官方來源責任與報告欄位說明，遵循 ADR-0004。正式插件目錄仍依 ADR-0002，不全面改寫目錄政策或新增傳輸。
- [ ] 本票可由注入式完整 runner 與來源 fixture 展示動態選取及報告，不發 live 推理請求。

## Context

官方模型目錄既有回應僅有基本識別欄位，不能假設具有費率或端點。使用固定的官方來源 fixture 驗證現有接縫，不把當時模型數量或範例 ID 寫成驗收白名單。適用 C1、Q1–Q5、S1–S3、D1/D2。

正式發布時設定 `Status: open`、`Labels: ready-for-agent`。
