# 使用指南

[English](usage.md) | **繁體中文**

安裝方式與精確版本需求請先閱讀 [README](../README.zh-TW.md)。
本指南說明目錄更新、探測、快取復原與選用 key。

## 模型目錄與更新

- [models.dev](https://models.dev) 提供免費模型資料，包括上下文限制與已發布的能力；
  Zen 的 `/inference/v1/models` 決定上游目前仍列出哪些項目。
- 更新採惰性觸發：過期後，下次讀取目錄才有資格重新整理，不保證在某個確切時間背景更新。
- models.dev 預設間隔為 24 小時；收到未變更回應（`304`）後縮短為 6 小時，
  資料有變更時回到 24 小時。
- Zen 清單有獨立的 30 分鐘間隔，啟動時也會重新讀取。清單請求不消耗推理額度。
- 更新失敗時保留最後可用的清單；沒有網路與快取時，退回 pi-ai 內建目錄。
- Zen 正在供應、但 models.dev 尚未提供資料的免費模型，會在詳情頁列為未知項目，
  不會猜測能力後放進模型選單。

## 模型開關與探測

在插件詳情頁隱藏不使用的模型。隱藏的模型不會被探測；模型開關屬於插件設定，
與目錄快取分開保存。

讀取模型清單時，每個本地日自動觸發一輪探測。「立即探測」可額外要求一輪，
最短間隔為 5 分鐘。**探測會送出真實推理請求並消耗額度**，模型逐一檢查，
通道回退可能需要額外請求。匿名額度由同一出口 IP 的呼叫者共用。

| 結果 | 意義與處理方式 |
|---|---|
| 已測得 | 模型在該輪有回覆；延遲不代表未來可用性的保證。 |
| 未測到 | 准入拒絕、額度、驗證身份、網路或其他無法判定的狀況。先閱讀橫幅；不會據此移除模型。 |
| 不可用 | 已檢查實作的通道後，收到明確的模型層級拒絕。持久保存的 `dead` 判定不會自動重探。 |
| Zen 清單不再列出 | 不在列時隱藏，重新列出時可恢復；這與持久保存的 `dead` 判定不同。 |

結果會跨重啟保留。補上 Zen key 不會清除持久判定，也不會讓上游不再列出的模型回來。
判定規則詳見 [ADR-0002](adr/0002-catalogue-source-of-truth.md)。

## 重新判定整份目錄

只有在你確定要捨棄快取資料與探測歷史時才使用，例如上游修復通道之後。
這不是額度耗盡或准入拒絕的修復方式。

1. 確認目標 DSH 行程使用的 `DSH_HOME`。有非空值時，快取位於
   `<DSH_HOME>/dsh-opencode-free/catalog.json`；否則位於該行程家目錄下的
   `~/.dsh/dsh-opencode-free/catalog.json`。Desktop 的 `DSH_HOME` 可能與 shell 不同。
2. 修改快取前，由你自行停止目標 DSH。Agent 停止或重啟 DSH 前，必須取得明確授權。
3. 備份後，**只移除 `catalog.json`**。保留 profile、憑證、其他插件檔案與
   `DSH_HOME` 的其餘內容。
4. 再次啟動 DSH。目錄會重新推導，下一輪探測將模型視為未探測過，並消耗推理額度。
   隱藏模型的偏好仍保留在插件設定中。

若需要舊結果，請保留備份。還原時先停止 DSH，再將備份放回同一路徑。
DSH 執行期間不要手動編輯快取欄位。

## 選用 Zen key

插件依以下順序讀取 key：

1. 插件 `config.apiKey`。
2. DSH 行程環境中的 `OPENCODE_API_KEY`。
3. 匿名 `public`。

在目標 profile 的 `cordis.patch.yml` 設定 `apiKey`，Desktop 尤其適合此方式：

```yaml
- id: opencode-free
  name: dsh-opencode-free
  config:
    apiKey: <your Zen key>
```

也可以在啟動 DSH 的環境設定 `OPENCODE_API_KEY`。修改插件設定後請重載；
修改 shell 變數不會改變已執行中的 DSH 行程。要回到匿名存取，請移除兩個 key 來源。
不需要修改憑證儲存或進行登入。

妥善保管 key、設定檔與原始除錯輸出。目前除錯記錄可能洩漏 Authorization 前綴及
上游錯誤內容，詳見[差距 G1](standards-gap.md#g1-debug-logs-include-authorization-fragments)。

### 驗證設定的路徑

設定檢查只能證明欄位存在，不能證明 key 有效。若你明確要求消耗額度的實際連線檢查：

1. 在目標 DSH profile 載入設定。
2. 選擇 **OpenCode Zen Free** 下的一個模型，送出一則短訊息。
3. 確認收到非空回覆，只記錄版本、profile、模型 ID 與去敏後的結果。
   失敗時，單憑上游錯誤不能證明 key 無效，也不要自動重裝或重試。

檢查環境變數 key 路徑時，先確認沒有被設定檔的 key 覆蓋。不要開啟原始除錯記錄來
檢視憑證。回覆只能驗證該模型與請求路徑，不代表工具或所有免費模型都已驗過。
更完整的真實宿主驗證見[相容性驗證指南](compat-run.md)；可能消耗整份目錄的額度，
必須另行取得授權。

> [!WARNING]
> `scripts/reverify.sh` 目前屬於歷史診斷工具，仍使用 `/zen/v1`、隨機 session 時間區段
> 與空工具宣告。燈號與退出碼不能驗證目前插件的准入或 key 路徑，請勿作為完成判定。
> 此腳本仍會送出真實請求，也可能印出上游錯誤；僅能從 clone 取得，不在套件 tarball 中。
