# 相容性驗證以官方動態免費對話模型為目標

**Status**: accepted, 2026-10-15.

每輪相容性驗證重新讀取官方 `/inference/v1/models`，以目前官方費率及端點資料辨識免費對話模型。models.dev 可補充能力與推理等級資料，但其資料缺席不能讓官方目標靜默消失。報告保存本輪快照供核對；下一輪重新取得資料，不使用寫死名單或上輪報告作為來源。

## 取捨

若直接使用插件目前可見的模型當目標，插件漏掉的新模型也會從驗收中消失，造成全部通過的假象。因此驗收目標須獨立於目前插件目錄。官方目錄目前未提供費率或通道欄位，須另外核對官方發布的資料；結構改變、分類不明或資料衝突時，報告未完成，不猜測、不靜默縮減集合。

驗收涵蓋所有官方在列的免費對話模型。非對話模型另列排除原因與官方依據，例如使用 `/systemone` 的 Jev；排除不是通過。免費對話模型若使用插件尚未支援的通道，仍須留在目標中並報告未通過，不能因插件缺少能力就排除。

## 與既有決策的關係

[ADR-0002](0002-catalogue-source-of-truth.md)繼續管理正式插件的模型目錄。本決策管理相容性驗證的目標來源，避免沿用正式目錄的缺漏。它不代表本次會新增通道或改寫使用者可見的目錄政策。

ADR-0002 中「Zen 不公開某個模型跑在哪個端點」是歷史前提；[目前官方文件](https://opencode.ai/v2/docs/console/models/)已公開模型端點表。後續設計不得把舊前提當作目前事實。

完整 L0／L1／L2、退出碼與資料保護條件見[相容性驗證指南](../compat-run.md)。[ADR-0003](0003-compat-run-not-in-ci.md)的有限額度、不進 CI 與 429 不確定判定繼續適用。
