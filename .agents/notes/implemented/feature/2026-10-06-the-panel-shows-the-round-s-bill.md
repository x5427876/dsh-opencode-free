# Agent Note: 面板把这一轮的花销说出来

Status: implemented

## Problem

服务端在上一条 Note 里给出了 `requests`（本轮实际发出的请求数）与 `pending`
（仍欠样本的模型），但**面板没有把它们画出来**。上一轮我把这最后一段回退了：
渲染块让 `tests/client-render.test.mjs` 的 harness 不稳（同文件另外 24 条渲染测试
全过，唯独执行到新块就抛出测试外的异步 `ReferenceError`）。

**那次我是放弃，不是查清。** 本条补上那一米，并把当时没查的东西查清了。

## Decision

1. **`readProgress` 带进 `requests` 与 `pending`**——缺任一个都渲染成
   「不显示账单」而不是「显示 0」。
2. **渲染挂在既有进度胶囊旁**：一轮结束后，胶囊里多一段
   `N 次请求 · M 个待测`（英文 `N requests · M still to measure`）。
3. **`t()` 增加 `{name}` 插值**——卡片此前只接受 `key`，任何需要带数字的文案
   都无法落地。这是一处能力补齐，不是本次功能的附属品。
4. 文案进**中英两本字典**（U3），由既有的 parity 测试守住键集。

## 上次为什么会炸：查清了

渲染块本身没问题——`RAW11` 确实出现在渲染树里（用临时字面量验证过）。
炸掉的是**断言写错了对象**：我当时按「harness 不传 `t`，所以树上带的是字典键」
来断言，于是在断言一个**根本不会出现**的字符串。

真实情况相反：harness 的 `locale.register` 是空实现，但 bundle 内部自带
`translatorOf(ctx)`，卡片拿到的是**能查本模块字典并做插值的真实翻译器**，
所以树上出现的是**插值后的中文文案**，不是键。

也就是说：渲染从一开始就是对的，**是我用错误的期望去测它**，于是把正确的实现
回退了。教训不是「harness 不稳」，而是**在放弃之前先把失败读到底**——
我保存下来的那条 Note 写的是「harness 不稳」，那是一个未经查证的归因，
和 ADR 里那些没有锚点的断言是同一类错误。

## Alternatives considered

- **把账单放进「本轮有模型没测到」那条提示里**——那条提示只在有未测模型时出现；
  「全部测完但花了 45 次请求」同样需要被看见，所以账单不能寄生在它上面。
- **只在详情里显示，不放进胶囊**——详情要展开才看到，而「花了多少」是点完探测
  第一眼就该知道的数字。
- **不给 `t()` 加插值，改成 `t('bill') + n + t('bill.pending')`**——三段拼接比一个
  带参数的键更难翻译（语序会错），且中英都要维护两处。不加。

## Consequences

- **收益**：用户点完探测能看到「这轮花了 23 次请求，还有 2 个模型在测」，
  而不是只有「13/13」——后者无法区分「测完了」与「每个模型都被拒了」。
- **代价与已知上限**：胶囊变长一行；`opf-capsule` 是 `white-space: nowrap` 的药丸，
  段落文案已尽量短。超长语言或更大数字下可能溢出，属 UI 细节，下一轮看截图再调。
- **无回归**：字典 parity 测试（zh/en 键集相同）通过，说明两本文案同步。
