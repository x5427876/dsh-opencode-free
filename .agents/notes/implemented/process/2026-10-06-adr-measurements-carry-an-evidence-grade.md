# Agent Note: ADR 里的「实测 N」必须带证据等级

Status: implemented

## Problem

我在 2026-10-06 把「`muse-spark-1.3` 的 `max` 被扣住」列为待办，依据是
[ADR 0004 §三十三](../../../../docs/adr/0004-measured-capability-alignment.md)：

> at 516 reasoning tokens — the strongest mode that model has, confirmed twice.

使用者纠正：**该档位不对个人开放**。核对后发现，持久语料
`tests/measured-samples.json` 里这一行是

```
muse-spark-1.3-contributor-free, question=max  →  http: 200, tokens: null, n: 1
```

**一个 token 数都没有**，而 `.scratch/probe/` 下的原始 JSON **不入库**（ADR §三十九）。
所以「516」在全仓库找不到出处——它是一次性 harness 的结论，只存在于那份没人会再打开的快照里。

错��不在读取，而在我**把一份没有锚点的断言当成既成事实转述**。这条损伤路径不需要任何 bug：
只要 ADR 里有一句话读起来像事实，下一个读者（很可能又是我）就会照着它行动。

## Decision

给 ADR 0004 加一节 **§四十 证据等级**，逐条标明哪些数字在持久语料里有锚点、哪些只有一次性快照，
并写出两条对后人的硬要求。

量化结果（脚本在 `.scratch/verify/`，零配额，只读语料）：

| 等级 | 条目 |
|---|---|
| **有锚点** | big-pickle `minimal` 0/8、`low` 164；space-bunny `low` 0/9/22/37、基线 35；mimo-v2.6 基线 37、`none` 0；longcat `none` 71/80、`minimal` 36；nemotron-3-ultra 基线 49；nemotron-3.5 基线 30 |
| **无锚点** | muse-spark-1.2 `minimal` 47；muse-spark-1.3 省略 166/184；fledge 的 321/135/137 **字元数**（该模型不上报 `completion_tokens_details`，单位本就不同）；`max` 516（已作废） |

**muse-spark 家族同时是「锚点最弱」与「结论最肯定」的一族**——这一节点名它，
因为那正是我踩中的地方。

同时声明：**线上裁定不受影响**。`muse-spark-1.2/1.3` 现在的 `level-works/minimal`
来自 2026-10-06 的线上实测样本（`[17,12,11,31,34]` / `[31,18,19,16,21]`，
对基线 `[53,148,86]` / `[125,121,155]`），不是来自这些无锚点的数字。

## Alternatives considered

- **把无锚点的条目直接从 ADR 删掉**——读者会以为它们从未被测过，而它们**确实**被测过，
  只是结论无法复现。删掉会丢掉「曾经观察到、但证据不在了」这个事实，那正是需要留下的东西。
- **把 `.scratch/probe/` 的原始 JSON 入库**——给所有断言补上锚点。这是最彻底的做法，
  但 ADR §三十九 明确不收：它们是含本机路径的一次性 harness，且**入库等于把
  「当时某台机器上的一次观测」升级成仓库的事实**。分级是更诚实的中间态。
- **不写这一节，只在自己的笔记里记住**——下一位读者看不到。今天的错误正是
  「文档读起来像事实」造成的，个人笔记挡不住它。

- **在 CI 里加一条检查，断言 ADR 里出现的数字都能在语料里找到**——正则去匹配中文文档里的
  数字并与语料比对会产生大量误报（编号、行号、百分比），且把文档格式与数据结构焊死。
- **给语料补齐 muse-spark 的 token 样本**——需要重新发请求消耗共享桶，而那些数字**本身
  就是错的**（`max` 不对个人开放）。补齐错的数字只会制造新的错误锚点。

## Consequences

- **收益**：ADR 里最容易被当成事实转述的几条，现在自己声明了自己的证据等级。
  这是本次事故的**制度性**修复——代码层面的修复（自述不解锁档位）已经落地，
  这一条防止的是「下一次同类事故」。
- **代价与已知上限**：分级是**人工**判定的，会过时——新增语料后应当重跑脚本并更新本节。
  这一点写在本节的量化说明里（「腳本見 `.scratch/verify/`，零配額」），
  但那个脚本同样不入库，所以下一个维护者需要重写它。可接受：分级的**目的**是让人知道
  该不该信，重写成本远低于一次错误转述的代价。
- **未改变任何行为**：纯文档。

## Verification

- 脚本 `.scratch/verify/`（零配额、只读语料）逐条比对 ADR 断言与
  `tests/measured-samples.json`，输出即本节那张表。分类器回放测试
  （`tests/measured-corpus.test.mjs`）保证语料本身仍可复算。
- 文档改动，无代码风险；`pnpm run check` 全绿。
