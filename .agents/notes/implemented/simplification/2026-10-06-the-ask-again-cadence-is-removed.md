# Agent Note: 去掉「再问一次」的节奏

Status: implemented

## Problem

退避（`UNREACHABLE_BACKOFF_MS`：0 → 6h → 24h → 7d，按连续失败次数索引）是
ADR 0004 引入的一条**成本纪律**，理由是共享匿名桶：2026-10-06 实测
`ling-3.1-flash-free` 连续七次 429。

它在本会话里同时造成了三个可见后果，每一轮都在制造新的取证困难：

1. **能力行会消失几个小时再回来**。一��被测出「证据不足」的模型在自愈时被作废裁定，
   而它的退避条目还在，于是用户看到 Off 行凭空消失，要等到退避到期才可能回来。
2. **每次现场核查都要先读一遍退避表**，才能解释「为什么这一轮少测了几个模型」。
3. **它成了隐藏模型的逃逸口**（上一条 Note 已把自动轮的范围改成不问隐藏模型，
   本条把这条口彻底封掉）。

使用者的判断是：**这个环节不需要。** 这是对成本与收益的重新权衡，由维护者拍板。

## Decision

**整段机制删除**，不是绕过：

| 删除 | 位置 |
|---|---|
| `UNREACHABLE_BACKOFF_MS`／`ReachRecord`／`reachAllowsAttempt`／`nextReachAttempt`／`readReach` | `catalog.ts` |
| `CatalogState.reach`、`CatalogCacheRecord.reach` 与三处写盘点 | 同上 |
| `planRound` 的 `reach` 参数与 `reachAllowsAttempt` 过滤 | 同上 |
| 失败分支里推进节奏的三行、`ok` 分支里清零节奏的九行 | 同上 |

删除后 `probeMode` 之外没有残留引用，缓存里的旧 `reach` 字段被读盘忽略（它是可选的），
不会被写回。**这是唯一一处仍会读取但不再使用的历史字段**，记在这里以免后来者以为它还有用。

## 上界的形状（为什么这不贵）

删除后，一个够不着的模型每轮**只花一次请求**：探针的 shot 循环在 `inconclusive`
上直接 `break`，只有**能作答**的模型才会继续消耗采样预算。所以最坏情况是
「每轮 = 在场模型数」次请求，而不是「每轮 = 在场模型数 × 9」。

13 个模型的全在场情况下：每日自动轮 13 次/天（它本来每模型只花 1 次），
手动轮最坏 13 次（此前退避生效时可能接近 0）。

## Consequences

- **收益**：轮次的行为变得**可预测且无需解释**——每一轮都问在场每一个模型，
  没有「为什么这个没被问」的第二种解释。现场核查第一次不需要先读退避表。
- **代价与已知上限**：共享桶上的模型被 429 限流时，每轮仍会消耗 1 次请求。
  ADR 记录的那七次 429 会变成**每天七次**（若它每天都限流）。这是使用者接受的代价。
- **恢复语义简化**：此前「模型答不上来」会写入一条节奏，于是**轮次之间**存在状态；
  现在轮次之间唯一的持久状态是 `probes`（裁定与样本）与 `lastProbeAt`（每日节流）。
  **每日自动轮仍每天最多一次**（`probedToday`），所以「每天」这个节律没有丢。
- **删除的三条测试**（`a model that cannot be reached is asked less`、
  `the reach cadence round-trips`、`an answer resets the ask-again cadence`）
  换成一条**钉住新契约**的测试：连续三轮，每轮都问那个上一轮失败的模型。
- **不影响**：`dead` 仍是永久终局（`isSettled`），不会被重新问；
  手动轮的 5 分钟下限（`FORCED_PROBE_MIN_INTERVAL_MS`）**仍在**——那是防止连点花光额度，
  与「模型够不着」无关。

## Alternatives considered

- **只把阶梯拉平（全部改成 0）**——保留机制与状态，让它退化成「什么都没做」，
  但三处写盘点、`state.reach`、读盘与那个过滤条件全部变成死代码。删除更诚实。
- **保留退避但只对连续失败 ≥3 次的模型启用**——规则更聪明，但「阈值取几」没有依据，
  且使用者要的是去掉这个环节，不是把它调得更聪明。
- **把 5 分钟下限也去掉**——那是另一件事：它防的是**使用者自己**连点，
  与模型是否够不着无关。留着。
