# Agent Note: 错标的裁定在读的时候就地更正，不等下一次测量

Status: implemented

## Problem

上一条 Note 修好了「确认时从拼写推导种类」这个**来源**，并如实写了一句代价：

> 已有的裁定不会被追溯更正……会等 30 天 TTL 到期或声明变化才重量。

**那句话本身是错的推理。** 它把「修复写入路径」当成了「修复已有数据」的唯一途径，
而裁定是**它自己样本的纯函数**，样本就躺在同一条记录里：

```
longcat-2.5-preview-free
  effort: { kind: "level-works", level: "minimal" }   ← 旧代码写的
  effortTokens:         [1, 36, 36, 36, 36]            ← 中位数 36
  effortBaselineTokens: [36, 36, 36]                   ← 阈值 0.43 × 36 = 15.48
```

复算一次就知道它**什么都没降低**。所以「等 TTL」不是保守，是**在等一个记录里已经有的答案**，
而且还白白多花一次上游请求。

## Decision

**读盘时用样本重算裁定的种类**（`correctedEffortKind`，在 `readProbes` 里）：

| 重算结果 | 写回 |
|---|---|
| `verdict === undefined`（没有样本可比） | **不作任何声明**——与「无证据裁定」那条规则同一处置 |
| `true`（确实降低） | 保留档位：`level-works`／无档位则 `none-works` |
| `false`（没有降低） | **`noop`，且清掉 `level`** |

因为读盘在写盘之前，改好的裁定**会被下一次写盘持久化**——不是每次启动临时纠正一遍，
而是**一次更正，之后磁盘上就是对的**。

`rejected` 豁免：它由拒绝决定，不由中位数决定，没有可复算的东西。

## Alternatives considered

- **在写盘前更正一次（一次性脚本）**——能修好当前这条记录，但下一次别人升级、或者
  另一条记录同样被贴错标签时，又要再写一个脚本。读侧重算是**规则**，脚本是**事件**。
- **把错标签的裁定丢弃，让它重新测量**——比保留样本更慢：要多花 8 次请求才能得到一个
  记录里**已经写着**的答案。
- **在应用侧（`measuredEffortFor`）重算而不是读盘**——同样能让面板立刻显示正确，但
  磁盘上仍然是错的，下一次写盘会把错值再写回去。读盘是唯一能让更正**持久**的位置。

## Consequences

- **收益**：`longcat` 在**下一次启动**后就变成 `noop` → `off: null`，
  **不花一次请求，不等 30 天**。而且这条规则是通用的——任何被旧代码贴错标签的历史裁定
  都会在读取时被更正，不需要逐个手工修。
- **根因被封在读侧**：写入路径已经不再产生错标签，读侧又把存量改对。**两端都对了**，
  所以这不是「临时兜底」，而是**存量的永久归正**。
- **代价与已知上限**：读盘多一次纯计算（每条记录一次中位数比较），无网络、无状态。
  一个「样本支持 `level-works`、但当时问的其实是 `none`」的历史记录会被改写成 `none-works`
  并丢掉 `level`——那是**更保守**的方向（不给档位而不是给错档位）。
- **信任边界变了**：以前「记录里的裁定」是被直接采用的，现在它是**被复算的**。
  这是本条 Note 的实质：证据在记录里，结论就该从证据来。
