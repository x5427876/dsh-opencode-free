# Agent Note: 证据被代码删掉的裁定，不该被采信

Status: implemented

## Problem

上一条 Note 把「冻结的是计数，不是证据」修好了：新写的裁定会带着它的样本。但**已经被旧版本写下的裁定不会自己好起来**——它们的样本在 0.3.1 的确认路径里被清空，而缓存里留着的是「一个冻结的、没有任何证据支撑的裁定」。

线上证据（2026-10-06）：`longcat-2.5-preview-free` 的记录是

```
effort: { kind: "level-works", level: "minimal", … }
effortFrozenAt: …
effortTokens: []          ← 证据已被产生它的代码删除
effortBaselineTokens: [36, 36, 36]
```

而 ADR 0004 §三十一 记着该模型的 `minimal` 是 36、省略基线 36–45，**没有降幅**，表格里它的结论是 `off: null`。也就是说：这个模型正在向使用者提供一个**证据已被销毁、且与记录矛盾**的 Off 行。

更一般的形态是：**任何中位数类裁定在没有样本时都无法被复算**，而插件却把它当作「30 天内不要再问」的既成事实。这类裁定不只是可能错——它们让插件**停止去查**。

## Decision

读盘时判定：**中位数类裁定没有样本，就不是裁定。**

- `none-works`／`level-works`／`noop` 都是 `median(candidates) < 0.43 × median(baseline)` 得出的。样本没了，这个式子无法重算，因此裁定**连同 `effortFrozenAt` 一起丢弃**，该模型在下一轮被重量。
- **`rejected` 豁免**：它由「被拒绝」而不是中位数决定，本来就不会产生 token 样本——要求它有样本是错的。
- 判据在 `readProbes`（防御性读取器）里，与「旧仪表样本作废」是同一条思路的第二例：**测量格式变了，测量就要重来**。

这是自愈的，不需要用户删文件、不需要我动他们的状态——重启一次即可。

## Alternatives considered

- **由我直接删掉用户缓存里 longcat 的那条记录**——能立刻解决这一个模型，但把「代码写出了不可复算的裁定」这个缺陷留在原地，下一个部署同样中招；而且修改用户状态这件事本身应该由插件按规则做，不是由我手工做。
- **保留裁定但标记为「不可信」并在面板上提示**——保留了一个我们知道存疑的控件，用户会照着用。不可信的控件应当不存在。
- **在写入侧拒绝产生无证据的裁定**（即要求确认路径必须带着样本）——那是上一条 Note 已经做的；本条处理的是**已经落盘的历史**，写入侧管不到。
- **把 `EFFORT_TTL_MS` 缩短，让它更快自然过期**——30 天内它照样被采信，且只是把问题推迟。没有解决「证据不在」这件事。

## Consequences

- **收益**：升级后，`0.3.1` 写下的每一个中位数类裁定都会自动作废并重量；用户的 `longcat` 会在下一轮被重新测量，拿到**带证据**的新裁定——如果 `minimal` 真的对它无效，新裁定会是 `rejected`／`noop` → `off: null`，能力行自己消失（这是正确的结果：撤销一个错误的承诺，不是保留它）。
- **代价与已知上限**：这些模型要重新花几轮请求。这是**一次性**的，且花在一个本来就存疑的答案上。
- **代价**：读盘多了一条判断，纯函数、无网络。
- **范围**：只作用于 `kind !== "rejected"` 的裁定。`noop` 也被丢弃——它同样由中位数得出，没有样本就无法复算它「无效」的依据。

## Verification

- `GUARD: a verdict whose samples were deleted reads as no verdict`：种入两份记录——longcat 那份是 0.3.1 的形状（冻结裁定 + 空样本），断言 `effort` 与 `effortFrozenAt` 都不被采纳；另一份是 `rejected` 裁定（没有样本是合法的），断言它**存活**。变异验证：把判据改成 `false`，第一条失败。
- 回归：269 条测试通过；活体写盘路径不受影响（新裁定总是带样本，`unsupported` 恒为 false）。
