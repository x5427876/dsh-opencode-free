# Agent Note: 量不了的轴，只问存活

Status: implemented

## Problem

上一条 Note 让「基线为零 → 放弃这条轴」生效了，证据是线上 `fledge-alpha-free` 一轮只花 2685 ms（1 次请求）而不是整个预算。但同一份线上记录暴露了它没做完的一半：

```
fledge-alpha-free  base=[0,0,0]  cand=[0,0,0,0,0,0,0]  q=none  tally=["rejected"]
```

上一轮是 6 个候选样本，这轮变成 **7**。

原因在**位置**：放弃的判断写在 `effortMeasurementPending`（循环条件）里，而一轮**总是先打一枪**再问「还要继续吗」。那一枪问的是**上一轮留下的拼写问题**（`effortQuestion: "none"`），于是：

- 每个模型每轮仍然发一次请求（比整预算好，但仍是本可以不发的）；
- 那次读数被归档成候选样本 → **数组每轮长 1，永不停止**。

也就是说：判断放在循环条件里，只能挡住「继续」，挡不住「开始」。

## Decision

把「这条轴不可判定」的判断从**循环条件**移到**问什么**——`nextEffortQuestion` 在基线够 3 个样本且中位数为 0 时直接返回 `"settled"`，与已确认的模型同一待遇。

于是对该模型：**只发存活请求**，不注入任何拼写，因此**什么也不归档**。`effortTokens` 不再增长，`effortQuestion` 也不会留下一个永远问下去的问题。

规则仍然只有一处（`effortAxisUndecidable`），但它现在决定的是**问题**而不是**要不要再来一枪**——后者只是前者的推论。

## Alternatives considered

- **在循环条件里再补一条「归档前先判断」**——两处规则，迟早会漂移；而且「不发请求」与「发了但不归档」是两套逻辑，只做后者仍留下无谓的请求。
- **把样本数组定长**——治标：数组不再无界，但每轮仍然发一次带拼写的请求，而那个问题的答案**永远不可能落地**。
- **给这类模型一个 `noop` 裁定**——那会向使用者声称「我们测过、它无效」。我们没有测过（上游根本没报这个字段），声称是错的。**保持未量测**。

## Consequences

- **收益**：`fledge-alpha-free` 每轮只花 1 次存活请求，且**不再积累任何样本**。测试跑三轮后断言基线仍是 `[0,0,0]`、候选数组仍是 `undefined`、没有遗留问题——即「放弃」是静止的，不是一次性的。
- **代价与已知上限**：该模型永远拿不到 Off 行。这是对的：我们量不到它的推理，`off: null` 是诚实的答案而不是缺陷。（ADR 0004 §33 另有一条出路：从串流 `reasoning_content` 的**字符数**读推理量——那是一个更弱的仪器，且 ADR 已记录 `fledge` 的推理量与其它仪器不同单位，不适合直接与 token 基线比较。）
- **代价**：多一个「看起来像 settled、实际是放弃」的分支。两者在行为上现在完全一致（只测存活、不归档），这正是想要的收敛——它们没有理由表现得不同。

## Verification

- `GUARD: a route that reports no reasoning stops being asked, not asked for ever` 扩展为：跑**三轮**之后，断言基线不增长、候选数组保持 `undefined`、`effortQuestion` 没有被立起来。变异验证：去掉 `nextEffortQuestion` 里那一行，测试失败。
