# Agent Note: 裁定被作废，就是「现在就去问」的理由

Status: implemented

## Problem

「无证据的裁定不采信」生效后，线上立刻出现了它的副作用：

```
ling-3.1-flash-free   effort=none-works  →  effort=null
longcat-2.5-preview-free  effort=level-works/minimal  →  effort=null
```

两个模型都正确地丢了裁定（它们的样本同样被 0.3.1 删掉了）——但它们的**退避条目还在**，于是模型被跳到 **01:35 / 02:00 JST** 才被重问。

用户看到的是：重启一次，**一个用了几天的 Off 行凭空消失**，然后要等六个小时才可能回来。这比「继续信任一个证据被销毁的裁定」更让人困惑——后者至少看起来是稳定的。

退避的语义是「**够不着**，少问」；而裁定被作废的语义是「**我们不知道**」。这两个是不同的状态，却共用了同一个计时器。

## Decision

**决定「我们不知道」是立刻去问的理由，不是继续等下去的理由。**

- `readProbes` 在丢弃裁定的同时，把被丢弃的 id 收集成 `droppedVerdicts` 带回给 `readCache`，挂在内存中的缓存记录上（每个写盘点都逐字段构造，所以**它永远不落盘**）。
- `adopt` 恢复退避表时，把这些 id 的条目**删掉**：它们立刻变成「可以问」。
- 其余退避条目**一律不动**——「够不着」那条纪律不受影响，测试专门钉住了这一点。

关键在**信号必须从做决定的地方传出来**：读侧把裁定删掉之后，`record.probes` 里就再也没有「它本来有裁定」这回事了。试图在恢复时反推（比较原始与净化后的记录）会把规则复制成两份。现在这个列表由 `readProbes` 直接产出——**丢弃的判断只有一处**。

## Alternatives considered

- **在 adopt 里比较原始缓存与净化结果来推断哪些被丢了**——规则出现两次（读侧判一次、这里再判一次），两处会漂移；这正是本仓库反复出问题的那类改动。
- **接受六小时等待，认为「少问」优先**——那要回答的问题是：用户刚看到能力消失时，我们要多久才能给出解释。答案是「可能永远不解释」。对一个**从未被证实**的能力，欠解释的代价高于多花一次请求。
- **丢弃时同时写一条可见的记录（面板提示）**——比现状好，但仍然要等退避到期才补上测量；本条是让补测量本身提前。
- **给被丢弃的裁定加 `unverified` 标记并继续提供**——把「我们不知道」变成「我们知道但不太确定」，而这不是事实。

## Consequences

- **收益**：升级后，被作废裁定的模型在**下一轮**（不是六小时后）就被重测。测试断言两件事：这个模型**现在**被问；而一个只是「够不着」的模型仍然被留着。
- **代价与已知上限**：一个既**确实够不着**、又**恰好**有无证据裁定的模型，会被多问一次。这是一次请求，且随后仍然是 inconclusive、退避照常恢复——上限是一次。
- **依赖**：`droppedVerdicts` 是内存字段。它不落盘（写盘点逐字段构造记录），所以重启后如果用户再次读同一个缓存，会**再算一次**并得到同样的结论——幂等，且不依赖上一次进程。
- **风险已消除**：读侧丢弃 + 恢复侧解禁必须成对存在。若只做前者（上一条 Note），用户会看到能力消失且无人补测；若只做后者，则会无限追问一个不可判定的模型。两条 Note 合起来才是完整的。

## Verification

- `GUARD: dropping a verdict makes the model due again, not in six hours`：
  - 种入 0.3.1 的形状（冻结裁定 + 空样本）**加一条未到期的退避**，断言该模型**本轮就被问**；
  - 同一测试的另一半：一个只有退避、没有裁定的模型**仍然不被问**。
- 变异验证：去掉 `droppedVerdicts.push(id)`，第一条失败。
- 测试的时钟与缓存里的 `nextAt` 用**同一个时钟**表达（第一版用了墙钟，与夹具的 `t: 1_000_000` 不一致，导致变异没有被捕获——这本身是一次「测试能不能看起来对而其实错」的复现）。
