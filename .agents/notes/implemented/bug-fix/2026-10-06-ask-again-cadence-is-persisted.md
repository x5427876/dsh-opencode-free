# Agent Note: 「再问一次」的节奏属于盘���，必须落盘

Status: implemented

## Problem

「不可达退避」（`UNREACHABLE_BACKOFF_MS`：0 → 6h → 24h → 7d）是为**共享额度桶**设计的：实测 2026-10-06，`ling-3.1-flash-free` 连续七次 429，这个阶梯存在的唯一理由就是别再花第八次请求。

而 `reach` 是三面都准备好了、只有中间那一面没接上的字段：

| 一面 | 状态 |
|---|---|
| `readCache` → `readReach(parsed.reach)` | 已实现 |
| `adopt` → `state.reach = { ...record.reach }` | 已实现 |
| `writeCacheAtomic` → `payload.reach = record.reach` | 已实现 |
| **三个 `writeCacheAtomic(path, …)` 调用点** | **都没传这个字段** |

`writeCacheAtomic` 是**整条替换**记录，所以每一次写盘都把节奏删掉了——包括轮次自己刚写下的那一次。于是这个阶梯在进程内有效、重启即清零，而 DSH 正是那种每天重启好几次的东西。

现场数据里 `catalog.json` 根本没有 `reach` 这个键，与此一致。

## Decision

三个写盘点全部带上 `reach: state.reach`：

1. **轮次收尾的写**——它刚推进过节奏，不写就等于没推进。
2. **同步（304）分支的写**——同步不是轮次，但它的写同样替换整条记录。
3. **同步（拿到 body）分支的写**——同上；这条分支还在内存里重建 `state.cache`，那里也一并带上，于是 `adopt(state, deps, state.cache)` 重建出的状态与磁盘一致。

第 3 条里原先有一段「把 `previousReach` 条件展开」的写法，是本决定落地时的产物，随即被删掉：`state.reach` 本身就是那个唯一副本，`adopt` 早已把它读进来，再从 `state.cache` 取一次是第二个来源。

## Alternatives considered

- **不落盘，改成「重启即清零」并写进文档**——更简单，且方向上不算危险（多问一次，而非少问）。但它使阶梯在最需要它的场景里失效：用户重开 DSH、换一个模型试试、再重开，每一次都在重问那个已经 429 七次的模型。ADR 0004 §38 第七条写的是「收敛是概率性的，且现在有界」——不落盘时它没有界。
- **把 `reach` 合并进 `probes`**（每个模型一条记录里带 misses/nextAt）——少一个顶层字段。但 `reach` 的设计初衷正是**不写进 `ProbeRecord`**：一轮什么都没测到的模型不得在那里留下任何东西（注释明写「Deliberately NOT a ProbeRecord」）。合并会打破这条纪律，正是本仓库反复出问题的那类改动。
- **只在轮次写盘时带，同步不带**——能覆盖主要场景，但同步每天最多四次，每次都会把刚写下的节奏删掉。实测过的正是这个形状。

## Consequences

- **收益**：退避阶梯第一次真的跨过重启；共享桶不再因为用户重开 DSH 而被反复试探。
- **代价与已知上限**：一个落盘的 `nextAt` 是**绝对时间戳**，所以跨天之后它可能已经过期（无害：过期即「现在可以问」）或者还很远（也符合本意）。时钟被人为拨快会让退避变短——这是所有基于时间的退避共有的性质，不是本决定引入的。
- **代价**：记录变大一点点，且多一个需要向前兼容读的字段。`CACHE_VERSION` **不**因此 bump：旧缓存没有这个键时读作「没有节奏」，即一切照常被问到——那正是升级前后的行为，不需要迁移。
- **范围**：`readReach` 的防御性读取早已存在且被测试覆盖；本决定只补写侧。

## Verification

- 具名测试 `GUARD: the ask-again cadence survives a write and a restart`：一轮 429 之后断言磁盘上 `reach[id].misses === 1`；再断言一次目录同步之后它仍在；最后用同一个文件起一个新容器，断言它在自己的退避窗口内**不再发起请求**。变异验证：从轮次写盘点删掉 `reach`，第一条断言立刻失败。
